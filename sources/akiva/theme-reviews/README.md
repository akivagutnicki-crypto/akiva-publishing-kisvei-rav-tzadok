# Whole-library connection review

The scope is every canonical book, section, and subsection in both schools. An
approved connection at one anchor does not complete the surrounding subsection,
section, or book. Reading a complete section for one comparison also does not
complete the search for all its subsections.

The current canonical inventory is generated by
`scripts/build-theme-review-progress.mjs`. It selects the same default edition
used for reviewed conceptual records: an available canonical interlinear
paragraph takes precedence over an older Hebrew-only duplicate. Do not use an
older variant to rescue a quotation that no longer matches the default edition.

## Discovery and review are separate

`scripts/build-theme-candidates.mjs` locates **unreviewed candidates** throughout
the canonical corpus. `scripts/theme-review-packet.mjs` prepares the complete
Hebrew and existing English context for an editor. Neither tool approves a
connection, writes a review ledger, changes canonical text, adds a translation,
or writes anything under `dist/library`.

The discovery method uses exact normalized Hebrew and English tokens, actual
adjacent word pairs, and the publication's explicit citation metadata. It does
not use substring matching or stemming: `נחש` does not match `נחשב`. Homographs
such as `עצם` remain ambiguous. The editor must determine their meaning from the
complete argument.

Hebrew has greater retrieval weight than English. Citation evidence preserves
whether the citation is in the Hebrew body, English body, a footnote, or
unlocated published metadata. A shared whole daf is labeled as such; it is not
treated as a verified match to the same sugya. Only an exact canonical paragraph
citation identifies a direct target paragraph. Explicit section citations are
retained as complete section contexts without guessing a paragraph.

The score is a retrieval rank, **not a quality score, probability, semantic
verdict, or scholarly review**. Generic publication formulas are suppressed.
Each school receives its own shortlist; distinct works are offered before
repeated selections from one work. By default a shortlist has at most six
candidates, two from one work, and one from one section. A shorter or empty list
is allowed. These limits prevent a familiar Mei HaShiloach or Lech Lecha passage
from filling every position, while leaving all candidates subject to review.

This is exhaustive **enumeration**, not exhaustive conceptual understanding.
Lexical retrieval can miss a strong connection expressed in different words,
and can find a weak comparison through the same words. The editor must broaden
the search when the packet does not supply an illuminating comparison.

## Build the complete discovery worklist

Run after the final library data and MCP index have been built:

```sh
node scripts/build-theme-candidates.mjs
```

The default output is the ignored internal directory
`artifacts/connected-ideas/theme-candidates/`. Output overrides must remain under
the ignored `artifacts/connected-ideas/` tree. The tools reject publication and
editorial destinations and paths redirected by symlinks.

The output contains:

- `manifest.json`: corpus and implementation fingerprints, settings, the
  selected scope, every book's denominator, queried subsection counts, existing
  completed reviews, and the most frequently selected candidate passages.
- `documents.json`: every canonical subsection's exact reference, default
  edition, original paragraph/section indexes, Hebrew pins, and English
  availability.
- `corpus/`: an exact snapshot of the MCP catalog and text files, including full
  author text, original phrase pairs, headings, citations, and footnotes.
- `candidates/<book-slug>.jsonl`: one worklist entry per queried subsection,
  with separate candidate lists for both schools and explicit retrieval evidence.

Every generated entry remains `reviewed: false`. The manifest always reports
`completedReviewsCreatedByThisRun: 0`. Existing completion counts come only from
the validated published review-progress summary, and only where both current
Hebrew pins still match. New or changed subsections remain pending.
These counts describe the review summary captured in this discovery snapshot;
regenerate after publishing additional reviews to refresh that status.

For a faster first pass, query one whole book or an exact section while keeping
the entire corpus available as the target pool:

```sh
node scripts/build-theme-candidates.mjs --book divrei-chalomot --out-dir artifacts/connected-ideas/theme-candidates-divrei-chalomot
node scripts/build-theme-candidates.mjs --section "Peri Tzadik, Lech Lecha 1" --out-dir artifacts/connected-ideas/theme-candidates-lech-1
```

Book titles and slugs are both accepted. `--ref` selects one exact canonical
subsection. `--start` and `--count` optionally limit origins in canonical reading
order. `--start` is a **1-based subsection position within the selected scope**,
not a printed siman or ois number. The manifest retains the whole-corpus
denominator even when only part of it was queried.

## Generate a complete editorial packet

Use a whole-corpus snapshot to prepare any book:

```sh
node scripts/theme-review-packet.mjs --book divrei-chalomot
```

Use a book-only discovery snapshot and select an ordered batch:

```sh
node scripts/theme-review-packet.mjs --input artifacts/connected-ideas/theme-candidates-divrei-chalomot --book divrei-chalomot --start 1 --count 5
```

An exact section or subsection can also be selected:

```sh
node scripts/theme-review-packet.mjs --section "Peri Tzadik, Lech Lecha 1"
node scripts/theme-review-packet.mjs --ref "Takanat HaShavin 4:3"
```

The packet is written as JSON and readable Markdown under the snapshot's
`packets/` directory. A bounded origin selection still includes the **complete
originating section and complete candidate sections**. Repeated contexts are
included once and identified by a stable context ID. Published headings and
footnotes remain separate from the author's paragraph text. Exact section
citations are included without an inferred paragraph.

Each originating section also receives one **pending continuity review** with
the exact previous section, current section, and next section in canonical book
order. The complete neighboring contexts are included even when the selected
origin range is narrow. Neighbors stop at book boundaries. Duplicate editions
do not create extra neighbors, and multiple selected paragraphs share their
section's continuity worklist.

The previous/core/next editorial statements start empty, with empty required
supporting-reference fields. A section's position does not establish that it
continues a particular idea from the previous section or prepares the next one.
The editor must read the contexts and supply exact paragraph evidence for any
such statement. Imported examples of thematic threads can suggest a layout;
their summaries, quotations, and transitions must still be checked independently.

Packets verify the manifest, metadata, candidate-file, and canonical-file
hashes before using them. A changed or incomplete snapshot fails closed.
An enumerated subsection that has not yet been queried cannot silently produce
an empty “reviewed” packet; first extend the discovery scope.

English availability is reported as `missing`, `partial`, or
`present-for-all-Hebrew-phrases`. “Present” only counts existing fields. It does
not certify their accuracy. Translate missing passages and review the existing
translation against the Hebrew before approving a quotation. Preserve the full
thought, important qualifications, and the distinction between quotation and
editorial explanation.

## Complete an actual subsection review

1. Read the full origin section and identify the subsection's actual argument.
2. Read the proposed target passages in context, and examine both schools.
3. Reject shared words, citations, or general themes that do not illuminate the
   argument. Record the specific reason for rejection or deferral. Broaden the
   search where needed; the shortlist is not the universe of possible parallels.
4. For an approved relation, author a separate reviewed theme record under
   `sources/akiva/themes/`, following that directory's schema and validation.
   Pin the complete origin paragraph, origin section, and target paragraph.
   A reciprocal record also needs full target-section review, its pin, and
   direction-specific title, summary, and explanation.
5. Only when the subsection's actual review is complete, author its explicit
   ledger entry in this directory. Record both-school candidates actually read,
   their precise references, and substantive assessments. Use
   `reviewed-with-connections` or `reviewed-no-approved-connection` accurately.
   A no-approval decision does not assert that no useful comparison exists.
6. Run the relevant gates:

```sh
node scripts/test-theme-candidates.mjs
node scripts/build-connected-ideas.mjs --check
node scripts/build-theme-review-progress.mjs --check
```

The generated packet deliberately has no automatic approval/import path.
Retrieval evidence is never a substitute for the separate reviewed thematic
record and completed subsection ledger.
